### The hook: a pull request with nothing wrong

Ask an AI to finish the series' little clue.api — open a case, close a case — and it writes this — `demo/fat_router.py`, two endpoints, ~45 lines:

```python
from fastapi import FastAPI, HTTPException

app = FastAPI(title="clue.api", version="0.4.0")

# Storage and id generation live here too — module-level state.
CASES: dict[str, dict] = {}
_next_id = 1


@app.post("/cases", status_code=201)
async def open_case(body: dict) -> dict:
    # 1. parse + validate
    title = str(body.get("title", "")).strip()
    if not title or len(title) > 80:
        raise HTTPException(status_code=422, detail="title must be 1-80 chars")
    # 2. business rules and id generation
    global _next_id
    case_id = f"C-{_next_id}"
    _next_id += 1
    # 3. storage
    case = {
        "case_id": case_id,
        "title": title,
        "status": "open",
        "detective": None,
        "resolution": None,
    }
    CASES[case_id] = case
    # 4. response shaping — same function
    return case


@app.post("/cases/{case_id}/close")
async def close_case(case_id: str, body: dict) -> dict:
    case = CASES.get(case_id)  # storage, again
    if case is None:
        raise HTTPException(status_code=404, detail=f"no case {case_id}")
    if case["status"] == "closed":  # rule #1, inline
        raise HTTPException(status_code=409, detail="case already closed")
    if case["detective"] is None:  # rule #2, inline
        raise HTTPException(status_code=409, detail="assign a detective first")
    # rule #3, mixed into the storage write
    case["status"] = "closed"
    case["resolution"] = str(body.get("resolution", "")).strip()
    return case
```

It works. `curl` returns 201 with a tidy JSON case; closing before assigning returns a well-mannered 409. You would approve this PR, and you would be right by every line: no line here is wrong. Every line is just in the wrong *place* — parse, rules, ids, storage and response shaping, all one function.

This post is about that place. Four questions:

1. **Why the fat router wins every demo** — and what it costs from the second month on.
2. **What belongs in each layer** — web, service, data, and the test "which column is this line in?"
3. **The direction rule** — who may call whom, and the three arrows that are always bugs.
4. **What the split buys** — rules you can run without a server, storage you can swap without touching rules.

That is the trap: it passes. The rot starts at the first change that isn't an endpoint:

- **A second entrance appears.** A nightly script, a message consumer, a CLI — something else needs to close cases too. The rule "assign a detective first" lives inside `close_case`, so the new caller copies it, or worse, forgets it. Same rule, two homes, drifting.
- **Checking a rule needs the framework.** To answer "does closing refuse an unassigned case?", you boot uvicorn and curl. The rule is real, but nothing in the codebase can *call* it.
- **Storage is welded in.** `CASES` is a module dict that the rules read and write inline. Swapping it for a database means editing the same function that holds the rules — with the rules on screen, you will break one.

<BeP04RuleDrift />

Fowler's Service Layer pattern page describes the disease in one line: "encoding the logic of the interactions separately in each interface causes a lot of duplication." The fat router is that duplication with one interface so far.

<Callout type="warning" title="The AI habit to break">
You asked for an endpoint, and AI wrote an application inside it — because the endpoint is the only seam the prompt exposed. When you review generated code, the question is never "does it run?" It runs. The question is: *when the next rule, the next field or the next caller arrives, which file will it edit — and what else lives in that file?*

## 2. Three boxes, one job each

The fix is not a framework or a folder convention; it is an ownership rule. Three boxes, one job each — everything else follows.

<BeP04Belongs />

Here is clue.api, rebuilt as those three files. The data layer first — `demo/layered_data.py`, the whole file:

```python
from dataclasses import dataclass
from typing import Protocol


@dataclass
class CaseRecord:
    case_id: str
    title: str
    status: str
    detective: str | None = None
    resolution: str | None = None


class CaseRepository(Protocol):
    """The shape of storage, as the service layer sees it."""

    def add(self, record: CaseRecord) -> None: ...
    def get(self, case_id: str) -> CaseRecord | None: ...
    def save(self, record: CaseRecord) -> None: ...


class InMemoryCaseRepository:
    """Today's implementation: the records live in one process dict."""

    def __init__(self) -> None:
        self._cases: dict[str, CaseRecord] = {}

    def add(self, record: CaseRecord) -> None:
        self._cases[record.case_id] = record
        print(f"data    | add({record.case_id}) -> in-memory store")

    def get(self, case_id: str) -> CaseRecord | None:
        print(f"data    | get({case_id}) <- in-memory store")
        return self._cases.get(case_id)

    def save(self, record: CaseRecord) -> None:
        self._cases[record.case_id] = record
        print(f"data    | save({record.case_id}) -> in-memory store")
```

Two things to notice. `CaseRecord` is a plain dataclass — no ORM, no Pydantic, it is *ours*, the language the middle layer speaks. And `CaseRepository` is a `Protocol`, Python's shape-only interface: anything with `add`, `get` and `save` satisfies it, with no inheritance and no import of this file. Hold that thought for section 4.

The service layer — `demo/layered_service.py`, the whole file. This is the layer you own:

```python
from layered_data import CaseRecord, CaseRepository


class CaseNotFoundError(Exception):
    """The workflow asked for a case that storage does not have."""


class CaseRuleError(Exception):
    """A rule refused the move — the web layer maps this to a 4xx."""


def _trace(msg: str) -> None:
    print(f"service | {msg}")


class CaseService:
    """The case workflow, rules enforced at every move."""

    def __init__(self, repo: CaseRepository) -> None:
        self._repo = repo
        self._next_id = 1

    def open_case(self, title: str) -> CaseRecord:
        _trace("open_case: the id and the open status are ours to set")
        case = CaseRecord(case_id=f"C-{self._next_id}", title=title, status="open")
        self._next_id += 1
        self._repo.add(case)
        return case

    def get_case(self, case_id: str) -> CaseRecord:
        return self._require(case_id)

    def assign(self, case_id: str, detective: str) -> CaseRecord:
        case = self._require(case_id)
        _trace(f"assign({case_id}): rule — only an open case can be taken")
        if case.status == "closed":
            raise CaseRuleError("a closed case cannot be assigned")
        case.detective = detective
        self._repo.save(case)
        return case

    def close(self, case_id: str, resolution: str) -> CaseRecord:
        case = self._require(case_id)
        _trace(f"close({case_id}): rule — a case closes with a detective on it")
        if case.detective is None:
            raise CaseRuleError("an unassigned case cannot be closed")
        case.status = "closed"
        case.resolution = resolution
        self._repo.save(case)
        return case

    def _require(self, case_id: str) -> CaseRecord:
        case = self._repo.get(case_id)
        if case is None:
            raise CaseNotFoundError(f"no case {case_id}")
        return case
```

Every rule from the fat router now has one address. "Assign a detective first" is one `if` in one method, raising a domain error — not an HTTP status. The module imports no FastAPI, no HTTP anything; ask it "what does closing mean?" and it answers from its own code.

And the web layer — `demo/layered_app.py`, the only file that imports FastAPI:

```python
import time

from fastapi import APIRouter, FastAPI, Request
from fastapi.responses import JSONResponse
from pydantic import BaseModel

from layered_data import CaseRecord, InMemoryCaseRepository
from layered_service import CaseNotFoundError, CaseRuleError, CaseService


def _trace(msg: str) -> None:
    print(f"web     | {msg}")


repo = InMemoryCaseRepository()
service = CaseService(repo)

app = FastAPI(title="clue.api", version="0.4.0")
router = APIRouter(prefix="/cases", tags=["cases"])


@app.middleware("http")
async def trace_layers(request: Request, call_next):
    _trace(f"{request.method} {request.url.path} -> dispatch to a handler")
    started = time.perf_counter()
    response = await call_next(request)
    elapsed_ms = (time.perf_counter() - started) * 1000
    _trace(f"{response.status_code} back through the stack · {elapsed_ms:.2f} ms")
    return response


# Where domain errors become status codes: once, at the edge.
@app.exception_handler(CaseNotFoundError)
async def case_not_found(request: Request, exc: CaseNotFoundError) -> JSONResponse:
    return JSONResponse(status_code=404, content={"detail": str(exc)})


@app.exception_handler(CaseRuleError)
async def rule_refused(request: Request, exc: CaseRuleError) -> JSONResponse:
    _trace(f"rule refused: {exc}; mapping CaseRuleError -> 409")
    return JSONResponse(status_code=409, content={"detail": str(exc)})


class OpenBody(BaseModel):
    title: str


class AssignBody(BaseModel):
    detective: str


class CloseBody(BaseModel):
    resolution: str


class CaseOut(BaseModel):
    case_id: str
    title: str
    status: str
    detective: str | None
    resolution: str | None


def _out(case: CaseRecord) -> CaseOut:
    return CaseOut(
        case_id=case.case_id,
        title=case.title,
        status=case.status,
        detective=case.detective,
        resolution=case.resolution,
    )


@router.post("", status_code=201)
async def open_case(body: OpenBody) -> CaseOut:
    _trace("title parsed and validated; asking the service to open the case")
    return _out(service.open_case(title=body.title))


@router.get("/{case_id}")
async def get_case(case_id: str) -> CaseOut:
    _trace(f"{case_id} asked for; the service knows what exists")
    return _out(service.get_case(case_id))


@router.post("/{case_id}/assign")
async def assign(case_id: str, body: AssignBody) -> CaseOut:
    _trace("case_id and detective parsed; asking the service to assign")
    return _out(service.assign(case_id=case_id, detective=body.detective))


@router.post("/{case_id}/close")
async def close(case_id: str, body: CloseBody) -> CaseOut:
    _trace("case_id and resolution parsed; asking the service to close")
    return _out(service.close(case_id=case_id, resolution=body.resolution))


app.include_router(router)
```

Read the endpoints as a checklist of the web layer's whole job: parse (Pydantic models), ask the service, shape the response (`_out` → `CaseOut`). The `409` never appears in a router — the exception handlers translate domain errors to status codes once, at the edge. (The [lifecycle post](/blog/backend-http-request-lifecycle/) left clue.api as a skeleton whose `/cases/42` answered `open` to every id — there was no storage at all. Now you can see each layer the request crosses, because each one prints its boundary.)

Four FastAPI pieces carry that checklist, and each one earns its place. `@router.post("", status_code=201)` binds a function to a verb and path and sets the success status, so the function never says "201" in its body. The `body: OpenBody` parameter makes FastAPI parse and validate the JSON before your function runs; bad input is answered with a 422 and the service is never called. The `-> CaseOut` return type is what shapes the response: only those five fields leave, whatever else the record holds. And `@app.exception_handler(CaseRuleError)` registers one function that turns that exception into a response, wherever in the stack it was raised. `app.include_router(router)` then mounts all four endpoints under `/cases` in one line. The trap AI code falls into here is the opposite: `raise HTTPException(409)` from inside the service, which welds your rules to HTTP.

<Concepts>
- **Fat router**: an endpoint that parses, validates, decides, stores and responds in one function. Fine in a demo; every later change edits it.
- **Service layer**: the one home of business rules and workflow, callable from any interface — HTTP today, a queue or a CLI tomorrow.
- **Repository**: a collection-like interface over storage (`add`, `get`, `save` here). The service asks it for records, never for dicts, SQL or files.
- **Protocol**: Python's shape-only interface. No base class, no inheritance — any object with the right methods satisfies it, which is what makes the seam a seam.
</Concepts>

## 3. One direction only

Three layers would be decoration without the rule that keeps them honest: **a layer may call the layer below it, and nothing else.** Not sideways, not back up.

<BeP04Direction />

Each red X is a code smell you will actually meet:

- **The router opens the database itself.** Feels efficient — one less hop! Then the next endpoint does it, and the rules that were supposed to guard the write are now a convention, not a guarantee. The hop *was* the rule.
- **The storage layer invents rules.** An `if` creeps into the repository "just while we're here", and now every caller of the repo gets that rule whether they asked for it or not — including the script you wrote to backfill data, which needed to break it.
- **The service answers with status codes.** The moment a rule can return 409, it is married to HTTP; your CLI now prints `409` at a detective. Rules should raise *what happened*, and only the edge should decide *how to say it*.

The wiring makes the direction real, and the first version of it, `layered_app.py`, builds `service` as a module global that every endpoint reaches for. It works, but nothing in an endpoint's signature says it needs a service, and a test cannot hand it a different one. FastAPI has a feature for exactly this, `Depends`, and the file `demo/p04_depends.py` wires the same three layers with it:

```python
class CountedRepository(InMemoryCaseRepository):
    """The same store, plus a count, so ids can be derived from what is stored."""

    def __len__(self) -> int:
        return len(self._cases)


@lru_cache
def get_repo() -> CountedRepository:
    return CountedRepository()  # built once: the dict must outlive a request


def get_service(repo: CountedRepository = Depends(get_repo)) -> CaseService:
    service = CaseService(repo)  # a fresh, cheap service per request
    service._next_id = len(repo) + 1  # the id counter must not restart with it
    return service
```

Read it from the bottom. `get_service` declares that it needs a repository by naming `get_repo` in `Depends(...)`; FastAPI calls `get_repo` first and passes the result in. The `@lru_cache` is not decoration: the in-memory repository holds all the data, so it must be built once, while the service is cheap enough to rebuild per request. The same logic applies to the id counter: `CaseService` keeps `_next_id` on itself, so a service rebuilt per request would start at `C-1` every time and the second case would overwrite the first. The two extra lines in `get_service` derive the next id from what the repository already stores. (AI-written code often forgets the first half of this and builds the repository inside `get_service`, so every request sees an empty store and every case is "not found".) The endpoints then ask for the service in their own signature:

```python
@router.post("", status_code=201)
async def open_case(title: str, service: CaseService = Depends(get_service)) -> dict:
    return vars(service.open_case(title=title))


@router.post("/{case_id}/close")
async def close(
    case_id: str, resolution: str, service: CaseService = Depends(get_service)
) -> dict:
    return vars(service.close(case_id=case_id, resolution=resolution))

```

`service: CaseService = Depends(get_service)` says "give me a service" and nothing else: the endpoint does not know which repository sits underneath, or how it was built. It is still the web layer calling down one level. The only change is who does the wiring: your signature declares the need, FastAPI satisfies it.

## 4. What the split buys

**Rules without a server.** Because the service layer imports no FastAPI, you can drive the whole workflow with plain Python and a fake repository — `demo/layered_smoke.py`:

```python
from layered_data import CaseRecord, CaseRepository, InMemoryCaseRepository
from layered_service import CaseRuleError, CaseService


class FakeRepository:
    """Same shape as CaseRepository, none of the storage machinery:
    it keeps records in a list and counts the saves."""

    def __init__(self) -> None:
        self.records: list[CaseRecord] = []
        self.saves = 0

    def add(self, record: CaseRecord) -> None:
        self.records.append(record)

    def get(self, case_id: str) -> CaseRecord | None:
        return next((r for r in self.records if r.case_id == case_id), None)

    def save(self, record: CaseRecord) -> None:
        self.saves += 1


def run_scenario(repo: CaseRepository) -> None:
    service = CaseService(repo)
    case = service.open_case(title="The missing gnome")
    print(f"    opened {case.case_id}: {case.title}")
    try:
        service.close(case.case_id, resolution="given up")
    except CaseRuleError as exc:
        print(f"    close refused -> {exc}")
    service.assign(case.case_id, detective="wren")
    case = service.close(case.case_id, resolution="gnome found under the hydrangeas")
    print(f"    closed {case.case_id}: detective={case.detective}")
```

**Storage becomes a thing you swap.** That is not just test convenience; it is how the service survives its own success. The twelve-factor app treats a database as an *attached resource*: a deploy "should be able to swap out a local MySQL database with one managed by a third party... without any changes to the app's code" — only the handle in config changes.
```python
from fastapi import FastAPI, HTTPException

app = FastAPI(title="clue.api", version="0.4.0")

# Storage and id generation live here too — module-level state.
CASES: dict[str, dict] = {}
_next_id = 1


@app.post("/cases", status_code=201)
async def open_case(body: dict) -> dict:
    # 1. parse + validate
    title = str(body.get("title", "")).strip()
    if not title or len(title) > 80:
        raise HTTPException(status_code=422, detail="title must be 1-80 chars")
    # 2. business rules and id generation
    global _next_id
    case_id = f"C-{_next_id}"
    _next_id += 1
    # 3. storage
    case = {
        "case_id": case_id,
        "title": title,
        "status": "open",
        "detective": None,
        "resolution": None,
    }
    CASES[case_id] = case
    # 4. response shaping — same function
    return case


@app.post("/cases/{case_id}/close")
async def close_case(case_id: str, body: dict) -> dict:
    case = CASES.get(case_id)  # storage, again
    if case is None:
        raise HTTPException(status_code=404, detail=f"no case {case_id}")
    if case["status"] == "closed":  # rule #1, inline
        raise HTTPException(status_code=409, detail="case already closed")
    if case["detective"] is None:  # rule #2, inline
        raise HTTPException(status_code=409, detail="assign a detective first")
    # rule #3, mixed into the storage write
    case["status"] = "closed"
    case["resolution"] = str(body.get("resolution", "")).strip()
    return case
```

Cách sửa không phải thêm framework hay bày folder cho đẹp; đó là một quy tắc sở hữu. Ba tầng, mỗi tầng một việc — mọi thứ khác tự đi theo.

<BeP04Belongs />

Đây là clue.api dựng lại thành đúng ba file đó. Tầng dữ liệu trước — `demo/layered_data.py`, nguyên văn:

```python
from dataclasses import dataclass
from typing import Protocol


@dataclass
class CaseRecord:
    case_id: str
    title: str
    status: str
    detective: str | None = None
    resolution: str | None = None


class CaseRepository(Protocol):
    """The shape of storage, as the service layer sees it."""

    def add(self, record: CaseRecord) -> None: ...
    def get(self, case_id: str) -> CaseRecord | None: ...
    def save(self, record: CaseRecord) -> None: ...


class InMemoryCaseRepository:
    """Today's implementation: the records live in one process dict."""

    def __init__(self) -> None:
        self._cases: dict[str, CaseRecord] = {}

    def add(self, record: CaseRecord) -> None:
        self._cases[record.case_id] = record
        print(f"data    | add({record.case_id}) -> in-memory store")

    def get(self, case_id: str) -> CaseRecord | None:
        print(f"data    | get({case_id}) <- in-memory store")
        return self._cases.get(case_id)

    def save(self, record: CaseRecord) -> None:
        self._cases[record.case_id] = record
        print(f"data    | save({record.case_id}) -> in-memory store")
```

Hai điểm cần để ý. `CaseRecord` là dataclass thuần — không ORM, không Pydantic, nó là *của mình*, ngôn ngữ mà tầng giữa nói. Còn `CaseRepository` là một `Protocol`, kiểu interface khai báo hình dạng của Python: class nào có `add`, `get`, `save` là thỏa, không cần inherit, không cần import file này. Ghi nhớ điều đó cho phần 4.

Tầng service — `demo/layered_service.py`, nguyên văn. Đây là tầng bạn sở hữu:

```python
from layered_data import CaseRecord, CaseRepository


class CaseNotFoundError(Exception):
    """The workflow asked for a case that storage does not have."""


class CaseRuleError(Exception):
    """A rule refused the move — the web layer maps this to a 4xx."""


def _trace(msg: str) -> None:
    print(f"service | {msg}")


class CaseService:
    """The case workflow, rules enforced at every move."""

    def __init__(self, repo: CaseRepository) -> None:
        self._repo = repo
        self._next_id = 1

    def open_case(self, title: str) -> CaseRecord:
        _trace("open_case: the id and the open status are ours to set")
        case = CaseRecord(case_id=f"C-{self._next_id}", title=title, status="open")
        self._next_id += 1
        self._repo.add(case)
        return case

    def get_case(self, case_id: str) -> CaseRecord:
        return self._require(case_id)

    def assign(self, case_id: str, detective: str) -> CaseRecord:
        case = self._require(case_id)
        _trace(f"assign({case_id}): rule — only an open case can be taken")
        if case.status == "closed":
            raise CaseRuleError("a closed case cannot be assigned")
        case.detective = detective
        self._repo.save(case)
        return case

    def close(self, case_id: str, resolution: str) -> CaseRecord:
        case = self._require(case_id)
        _trace(f"close({case_id}): rule — a case closes with a detective on it")
        if case.detective is None:
            raise CaseRuleError("an unassigned case cannot be closed")
        case.status = "closed"
        case.resolution = resolution
        self._repo.save(case)
        return case

    def _require(self, case_id: str) -> CaseRecord:
        case = self._repo.get(case_id)
        if case is None:
            raise CaseNotFoundError(f"no case {case_id}")
        return case
```

Mọi luật từ thời router béo giờ có đúng một địa chỉ. "Phải gán detective trước" là một `if` trong một method, raise một lỗi của miền nghiệp vụ — chứ không phải một status code HTTP. Module này không import FastAPI, không dính dáng gì tới HTTP; hỏi nó "đóng case nghĩa là gì?", nó trả lời bằng chính code của mình.

Và tầng web — `demo/layered_app.py`, file duy nhất import FastAPI:

```python
import time

from fastapi import APIRouter, FastAPI, Request
from fastapi.responses import JSONResponse
from pydantic import BaseModel

from layered_data import CaseRecord, InMemoryCaseRepository
from layered_service import CaseNotFoundError, CaseRuleError, CaseService


def _trace(msg: str) -> None:
    print(f"web     | {msg}")


repo = InMemoryCaseRepository()
service = CaseService(repo)

app = FastAPI(title="clue.api", version="0.4.0")
router = APIRouter(prefix="/cases", tags=["cases"])


@app.middleware("http")
async def trace_layers(request: Request, call_next):
    _trace(f"{request.method} {request.url.path} -> dispatch to a handler")
    started = time.perf_counter()
    response = await call_next(request)
    elapsed_ms = (time.perf_counter() - started) * 1000
    _trace(f"{response.status_code} back through the stack · {elapsed_ms:.2f} ms")
    return response


# Where domain errors become status codes: once, at the edge.
@app.exception_handler(CaseNotFoundError)
async def case_not_found(request: Request, exc: CaseNotFoundError) -> JSONResponse:
    return JSONResponse(status_code=404, content={"detail": str(exc)})


@app.exception_handler(CaseRuleError)
async def rule_refused(request: Request, exc: CaseRuleError) -> JSONResponse:
    _trace(f"rule refused: {exc}; mapping CaseRuleError -> 409")
    return JSONResponse(status_code=409, content={"detail": str(exc)})


class OpenBody(BaseModel):
    title: str


class AssignBody(BaseModel):
    detective: str


class CloseBody(BaseModel):
    resolution: str


class CaseOut(BaseModel):
    case_id: str
    title: str
    status: str
    detective: str | None
    resolution: str | None


def _out(case: CaseRecord) -> CaseOut:
    return CaseOut(
        case_id=case.case_id,
        title=case.title,
        status=case.status,
        detective=case.detective,
        resolution=case.resolution,
    )


@router.post("", status_code=201)
async def open_case(body: OpenBody) -> CaseOut:
    _trace("title parsed and validated; asking the service to open the case")
    return _out(service.open_case(title=body.title))


@router.get("/{case_id}")
async def get_case(case_id: str) -> CaseOut:
    _trace(f"{case_id} asked for; the service knows what exists")
    return _out(service.get_case(case_id))


@router.post("/{case_id}/assign")
async def assign(case_id: str, body: AssignBody) -> CaseOut:
    _trace("case_id and detective parsed; asking the service to assign")
    return _out(service.assign(case_id=case_id, detective=body.detective))


@router.post("/{case_id}/close")
async def close(case_id: str, body: CloseBody) -> CaseOut:
    _trace("case_id and resolution parsed; asking the service to close")
    return _out(service.close(case_id=case_id, resolution=body.resolution))


app.include_router(router)
```

Đọc các endpoint như một checklist của toàn bộ công việc tầng web: parse (Pydantic model), gọi service, định hình response (`_out` → `CaseOut`). Con số `409` không bao giờ xuất hiện trong router — hai exception handler dịch lỗi nghiệp vụ sang status code đúng một lần, ngay ở biên. ([Bài vòng đời request](/blog/backend-http-request-lifecycle/) để lại clue.api là một bộ khung mà `/cases/42` trả `open` cho mọi id — vì hồi đó chưa có lưu trữ. Giờ bạn nhìn thấy từng tầng mà request băng qua, vì từng tầng tự in ranh giới của mình.)

Bốn mảnh của FastAPI gánh cái checklist đó, mỗi mảnh có lý do riêng. `@router.post("", status_code=201)` gắn một hàm vào verb và path, đồng thời chốt status thành công, nên thân hàm không cần viết "201". Tham số `body: OpenBody` khiến FastAPI parse và validate JSON trước khi hàm của bạn chạy; input sai bị trả 422 và service không bao giờ bị gọi. Kiểu trả về `-> CaseOut` quyết định hình dạng response: chỉ năm field đó đi ra, record có thêm gì cũng mặc. Còn `@app.exception_handler(CaseRuleError)` đăng ký một hàm biến exception ấy thành response, bất kể nó bị ném từ chỗ nào trong stack. `app.include_router(router)` gắn cả bốn endpoint vào `/cases` trong một dòng. Cái bẫy AI hay dính là ngược lại: `raise HTTPException(409)` ngay trong service, hàn chặt luật vào HTTP.

<Concepts title="Giải thích nhanh mấy thuật ngữ ở trên">
- **Router béo (fat router)**: endpoint tự parse, validate, quyết định, lưu trữ và trả response trong một hàm. Demo thì rất ổn; về sau mọi thay đổi đều sửa vào nó.

- **Protocol**: interface khai báo hình dạng của Python. Không base class, không inheritance — object nào có đúng các method là thỏa, và đó chính là thứ biến đường ranh giới thành một đường nối tháo được.

## 3. Chỉ đi một chiều

Ba tầng chẳng khác nào trang trí nếu thiếu quy tắc giữ cho chúng đứng đắn: **một tầng chỉ được gọi tầng ngay dưới nó, không hơn.** Không đi ngang, không quay ngược.

<BeP04Direction />

Mỗi dấu X đỏ là một code smell bạn sẽ gặp thật:

- **Router tự mở database.** Nghe hiệu quả — khỏi chặn thêm một chặng! Rồi endpoint kế tiếp cũng làm vậy, và những luật lẽ ra canh thao tác ghi giờ thành "lệ tên", không còn là bảo đảm. Chặng bị bỏ qua đó *chính là* luật.
- **Tầng lưu trữ tự đặt ra luật.** Một câu `if` lẻ loi len vào repository "tiện tay thôi", và mọi bên gọi repo đều dính luật này dù có muốn hay không — kể cả script backfill dữ liệu của bạn, thứ vốn cần phá luật.
- **Service trả về status code.** Luật mà trả được 409 là coi như đã cưới HTTP; CLI của bạn giờ in `409` ra mặt thám tử. Luật nên raise *chuyện gì đã xảy ra*, còn việc *nói nó thế nào* chỉ thuộc về biên.

Cách wiring làm cho chiều phụ thuộc thành thật, và bản đầu tiên, `layered_app.py`, dựng `service` thành biến global của module để mọi endpoint với tay lấy. Chạy được, nhưng chữ ký endpoint không hề nói nó cần service, và test cũng không đưa được cho nó một service khác. FastAPI có sẵn tính năng cho đúng việc này, `Depends`, và file `demo/p04_depends.py` đấu ba tầng đó bằng nó:

```python
class CountedRepository(InMemoryCaseRepository):
    """The same store, plus a count, so ids can be derived from what is stored."""

    def __len__(self) -> int:
        return len(self._cases)


@lru_cache
def get_repo() -> CountedRepository:
    return CountedRepository()  # built once: the dict must outlive a request


def get_service(repo: CountedRepository = Depends(get_repo)) -> CaseService:
    service = CaseService(repo)  # a fresh, cheap service per request
    service._next_id = len(repo) + 1  # the id counter must not restart with it
    return service
```

Đọc từ dưới lên. `get_service` khai báo nó cần một repository bằng cách ghi `get_repo` trong `Depends(...)`; FastAPI gọi `get_repo` trước rồi truyền kết quả vào. `@lru_cache` không phải để trang trí: repository in-memory giữ toàn bộ dữ liệu nên chỉ được dựng một lần, còn service đủ rẻ để dựng lại mỗi request. Cùng logic đó áp dụng cho bộ đếm id: `CaseService` giữ `_next_id` ngay trên nó, nên service dựng lại mỗi request sẽ bắt đầu từ `C-1` lần nào cũng vậy và case thứ hai ghi đè case thứ nhất. Hai dòng thêm trong `get_service` lấy id kế tiếp từ những gì repository đang lưu. (Code AI viết hay quên vế đầu và dựng repository ngay trong `get_service`, thế là request nào cũng thấy kho rỗng và case nào cũng "không tìm thấy".) Rồi các endpoint xin service ngay trong chữ ký của mình:

```python
@router.post("", status_code=201)
async def open_case(title: str, service: CaseService = Depends(get_service)) -> dict:
    return vars(service.open_case(title=title))


@router.post("/{case_id}/close")
async def close(
    case_id: str, resolution: str, service: CaseService = Depends(get_service)
) -> dict:
    return vars(service.close(case_id=case_id, resolution=resolution))

```

`service: CaseService = Depends(get_service)` chỉ nói "đưa tôi một service": endpoint không biết bên dưới là repository nào, hay nó được dựng ra sao. Vẫn là tầng web gọi xuống đúng một tầng. Khác biệt duy nhất là ai làm việc đấu nối: chữ ký của bạn khai báo nhu cầu, FastAPI đáp ứng.

## 4. Tách rồi được gì?

**Luật chạy không cần server.** Vì tầng service không import FastAPI, bạn có thể chạy toàn bộ luồng việc bằng Python thuần với một repository giả — `demo/layered_smoke.py`:

```python
from layered_data import CaseRecord, CaseRepository, InMemoryCaseRepository
from layered_service import CaseRuleError, CaseService


class FakeRepository:
    """Same shape as CaseRepository, none of the storage machinery:
    it keeps records in a list and counts the saves."""

    def __init__(self) -> None:
        self.records: list[CaseRecord] = []
        self.saves = 0

    def add(self, record: CaseRecord) -> None:
        self.records.append(record)

    def get(self, case_id: str) -> CaseRecord | None:
        return next((r for r in self.records if r.case_id == case_id), None)

    def save(self, record: CaseRecord) -> None:
        self.saves += 1


def run_scenario(repo: CaseRepository) -> None:
    service = CaseService(repo)
    case = service.open_case(title="The missing gnome")
    print(f"    opened {case.case_id}: {case.title}")
    try:
        service.close(case.case_id, resolution="given up")
    except CaseRuleError as exc:
        print(f"    close refused -> {exc}")
    service.assign(case.case_id, detective="wren")
    case = service.close(case.case_id, resolution="gnome found under the hydrangeas")
    print(f"    closed {case.case_id}: detective={case.detective}")
```

**Cùng các endpoint, test qua HTTP, vẫn không cần kho thật.** Vì `get_repo` là một dependency, test có thể thay nó. Bản giả này giữ record trong một dict, nên test với tay vào `fake.records` theo case id được. `app.dependency_overrides` ánh xạ hàm gốc sang một hàm thay thế, còn `TestClient` gọi app ngay trong process nên không mở port nào. `demo/p04_override.py`:

```python
class FakeRepository:
    def __init__(self) -> None:
        self.records: dict[str, CaseRecord] = {}

    def add(self, record: CaseRecord) -> None:
        self.records[record.case_id] = record

    def __len__(self) -> int:
        return len(self.records)

    def get(self, case_id: str) -> CaseRecord | None:
        return self.records.get(case_id)

    def save(self, record: CaseRecord) -> None:
        self.records[record.case_id] = record


fake = FakeRepository()
app.dependency_overrides[get_repo] = lambda: fake
client = TestClient(app)

opened = client.post("/cases", params={"title": "The missing gnome"})
print("open   ->", opened.status_code, opened.json()["case_id"])

refused = client.post("/cases/C-1/close", params={"resolution": "given up"})
print("close  ->", refused.status_code, refused.json()["detail"])

missing = client.post("/cases/C-9/close", params={"resolution": "x"})
print("ghost  ->", missing.status_code, missing.json()["detail"])

fake.records["C-1"].detective = "wren"
```

**Lưu trữ thành thứ thay được.** Đó không chỉ là tiện lợi khi test; đó là cách service sống nổi qua chính thành công của nó. Twelve-factor coi database là một *attached resource*: một deploy "phải có thể thay database MySQL local bằng một dịch vụ bên thứ ba… mà không sửa gì code của app" — chỉ đổi handle trong config. clue.api của mình hôm nay là một dict trong bộ nhớ, nhưng interface đã có sẵn hình dạng một database thật cần (`add` để insert, `save` để update), nên bài tiếp theo của series sẽ thay dict bằng SQLAlchemy với engine thật mà `layered_service.py`, cả hai router lẫn exception handler, không đổi một dòng — và lời hứa đó là toàn bộ lý do `CaseRepository` tồn tại.

<BeP04WhereChangeLands />

<Callout type="note" title="Đừng tách thứ mình chưa có">
Ba file cho một script viết cuối tuần là nghi thức, chưa phải kiến trúc. Việc tách tầng bắt đầu có lời từ bên gọi thứ hai hay luật thứ hai — trước đó, một endpoint trung thực vẫn hơn ba file rỗng. Thước đo không phải số file; mà là bạn có nói được từng dòng đang sống trong ô nào không.
</Callout>

Thói quen duyệt code, gói trong một dòng: **mở endpoint do AI viết kế tiếp ra và hỏi từng dòng đang sống ở tầng nào.** Dòng parse — ổn, nó thuộc router. Dòng quyết định *case phải thỏa điều gì* — nó thuộc service, dù endpoint ngắn cỡ nào. Dòng chạm vào lưu trữ, tự đặt luật, hay hardcode status code trong một luật — đẩy xuống một tầng. Bạn đang duyệt code đấy, nhưng bạn đang quyết định nơi sinh sống của cả sáu tháng thay đổi sắp tới.

</Vi>
