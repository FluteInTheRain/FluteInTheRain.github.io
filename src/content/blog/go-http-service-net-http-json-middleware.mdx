### The default server waits for ever

Cloudflare's guide to Go's `net/http` timeouts explains why that quote matters. A server with no timeouts waits for a slow or vanished client as long as the client likes. The guide warns that "very slow or disappearing clients might leak file descriptors", and the packaged shortcut `http.ListenAndServe` leaves every timeout off with no way to set them.

So the first rule of this post is to build the `http.Server` yourself and set its timeouts on day one. The rest of the service works the same way: the standard library gives you small parts, and you put them together yourself.

By the end you will have one JSON API in one `main.go`, its tests, and a container image built from nothing. It uses only the standard library, and it pulls together the series so far: structs and methods ([post 4](/blog/go-structs-methods-interfaces/)), errors and `recover` ([post 5](/blog/go-errors-defer-panic/)), table tests ([post 6](/blog/go-testing-table-tests/)), goroutines and channels ([post 7](/blog/go-goroutines-channels-select/)), and context and mutexes ([post 8](/blog/go-context-timeouts-mutexes/)). Every output below was captured on Go 1.27.1.

### Coming from Java, Python or JavaScript

| | Java (Spring Boot) | Python (Flask / FastAPI) | Node (Express) | Go (standard library) |

| Logging | SLF4J + Logback | `logging` | winston / pino | `log/slog` |
| Config | `application.properties`, env | env, `.env` files | `process.env` | `os.Getenv` |
| Per request | thread pool thread | worker or event loop | one event loop | one goroutine per connection |
| Shipping | jar + JRE image | Python + packages image | Node + `node_modules` image | one static file, image can be empty |

<Concepts>

- **Handler**: anything with a `ServeHTTP(w, r)` method. It reads the request `r` and writes the response to `w`.
- **ServeMux**: the router. It picks the handler by method and path pattern.
- **Middleware**: a function that wraps a handler to run code before and after it, such as logging.
- **Graceful shutdown**: stop taking new requests, let the running ones finish, then exit.
- **`FROM scratch`**: an empty container image. Your static binary is the only file in it.

</Concepts>

## What we are building

A tiny todo list API. It keeps todos in memory, so restarting the server empties the list; a database comes later in the series.

| Request | Does | Success status |
|---|---|---|
| `GET /healthz` | says the server is up | 200 |
| `GET /todos` | lists all todos | 200 |
| `POST /todos` with `{"title":"..."}` | adds a todo | 201 |
| `GET /todos/{id}` | returns one todo | 200 (404 if unknown) |

The project is one module with four files. A service this small does not need the `cmd/` and `internal/` folders from [post 1](/blog/go-first-program-modules-packages/#project-layout); add them when a second package appears.

```text
todo/
├── go.mod          module example.com/todo
├── main.go         the whole service
├── main_test.go    handler tests
└── Dockerfile      two stages, ends in FROM scratch
```

The snippets below are `main.go` from top to bottom, cut into parts. Put them back to back and you have the complete file.

## The data and the store

Start with the data. A request handler runs in its own goroutine, so two requests can touch the list at the same moment. The store guards its slice with a mutex, exactly as [post 8](/blog/go-context-timeouts-mutexes/) shows.

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"strconv"
	"sync"
	"syscall"
	"time"
)
```

```go
// Todo is one item. The tags tell encoding/json which key names to use.
type Todo struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
	Done  bool   `json:"done"`
}

// store keeps todos in memory. The mutex protects the slice because every
// request runs in its own goroutine.
type store struct {
	mu    sync.Mutex
	todos []Todo
}

func (s *store) add(title string) Todo {
	s.mu.Lock()
	defer s.mu.Unlock()
	t := Todo{ID: len(s.todos) + 1, Title: title}
	s.todos = append(s.todos, t)
	return t
}

func (s *store) get(id int) (Todo, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	if id < 1 || id > len(s.todos) {
		return Todo{}, false
	}
	return s.todos[id-1], true
}

func (s *store) list() []Todo {
	s.mu.Lock()
	defer s.mu.Unlock()
	out := make([]Todo, len(s.todos)) // a copy, and [] (not null) when empty
	copy(out, s.todos)
	return out
}
```

The backquoted text after each field, `` `json:"id"` ``, is a *struct tag*. It is a note attached to the field, and `encoding/json` reads it to choose the key name, so `ID` is written as `"id"`. Two details are easy to miss. `list` returns a copy, so a caller can never change the store's slice behind its back. It also uses `make`, so an empty store gives the JSON `[]` and not `null`, which many clients choke on.

## Routing with method and path patterns

A `ServeMux` is a table from patterns to handlers. Before Go 1.22 it only matched paths, and people reached for a router library to match methods and capture `{id}`. Since Go 1.22 the standard one does both: a pattern can start with a method and contain named wildcards, and the handler reads a wildcard with `r.PathValue`.

```go
type server struct {
	store *store
	log   *slog.Logger
}

// routes wires patterns to handlers and wraps them in middleware.
func (s *server) routes() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", s.health)
	mux.HandleFunc("GET /todos", s.listTodos)
	mux.HandleFunc("POST /todos", s.createTodo)
	mux.HandleFunc("GET /todos/{id}", s.getTodo)
	// The first middleware listed is the outermost one.
	return chain(mux, s.requestID, s.logging, s.recoverPanic)
}

func (s *server) health(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

func (s *server) listTodos(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, s.store.list())
}

func (s *server) getTodo(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.Atoi(r.PathValue("id"))
	if err != nil {
		writeError(w, http.StatusBadRequest, "id must be a number")
		return
	}
	t, ok := s.store.get(id)
	if !ok {
		writeError(w, http.StatusNotFound, "todo not found")
		return
	}
	writeJSON(w, http.StatusOK, t)
}
```

Three things happen here that the Go 1.22 routing post describes.

- `"GET /todos/{id}"` matches only GET (and HEAD) on `/todos/` plus one segment. `r.PathValue("id")` returns that segment as a string, and `strconv.Atoi` turns it into a number or an error.
- When a path matches but the method does not, the mux answers `405 Method Not Allowed` and fills in the `Allow` header itself. You will see that in the run below.
- When two patterns could both match, the more specific one wins, so `GET /todos/{id}` and `GET /todos/latest` can live side by side.

We create our own mux with `http.NewServeMux()`. The package also has a global `http.DefaultServeMux`, and any imported package can register routes on it, as *Efficient Go* warns when it discusses `net/http/pprof`. A mux you own has only the routes you wrote.

## JSON in, JSON out

The pattern for every endpoint is the same: decode the body, check it, do the work, write a JSON answer. The rest of `main.go` that deals with JSON is two small writers and one handler that decodes.

```go
type createRequest struct {
	Title string `json:"title"`
}

func (s *server) createTodo(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // refuse bodies over 1 MiB
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	var in createRequest
	if err := dec.Decode(&in); err != nil {
		writeError(w, http.StatusBadRequest, "invalid JSON: "+err.Error())
		return
	}
	if in.Title == "" || len(in.Title) > 100 {
		writeError(w, http.StatusUnprocessableEntity, "title must be 1 to 100 bytes")
		return
	}
	writeJSON(w, http.StatusCreated, s.store.add(in.Title))
}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(v); err != nil {
		slog.Error("write response", "err", err)
	}
}

func writeError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]string{"error": msg})
}
```

The decoding side is where services get hurt, so it has three guards.

1. `http.MaxBytesReader` caps the body at 1 MiB. Without it, a client can send a body as large as it likes and your server reads all of it.
2. `DisallowUnknownFields` turns a misspelled or extra key into an error instead of silently ignoring it.
3. The title check runs after decoding. JSON that parses can still be wrong.

The status codes carry meaning. A body that is not valid JSON, or has a key we do not know, is a `400 Bad Request`: the client sent something we cannot read. A body that is valid JSON but breaks a rule (an empty title) is a `422 Unprocessable Entity`: we read it and refuse it. Some teams use 400 for both; pick one rule and keep it. Errors always come back as `{"error": "..."}`, so a client has one shape to parse.

The order inside `writeJSON` matters: set headers, then `WriteHeader`, then the body. After `WriteHeader` the status line has gone to the client, so a failure while encoding can only be logged. That is why the error is logged and not returned.

## Middleware: a function from handler to handler

Some work belongs to every request: tag it with an ID, log it, survive a panic. Copying that into each handler would be noise, so Go uses *middleware*. A middleware takes the next `http.Handler` and returns a new one that does something, calls the next, and maybe does something after. It is a closure, from [post 5](/blog/go-errors-defer-panic/), that remembers `next`.

```go
// A middleware takes a handler and returns a handler that does extra work around it.
type middleware func(http.Handler) http.Handler

func chain(h http.Handler, mws ...middleware) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}
```

Two bits of syntax: `mws ...middleware` means `chain` accepts any number of middlewares, and `http.HandlerFunc(f)` turns a plain function into a `Handler`, so every middleware below can return a function literal. `chain` wraps the handler from the last middleware to the first, so the **first one listed is the outermost**. Back in `routes()`, `chain(mux, s.requestID, s.logging, s.recoverPanic)` means a request meets `requestID`, then `logging`, then `recoverPanic`, then the mux. The response goes back out the same way.

The first layer gives each request an ID. It keeps an ID the caller sent in `X-Request-ID` (useful when a gateway already made one) and otherwise makes 8 random bytes. It stores the ID in the request's context, the same context from [post 8](/blog/go-context-timeouts-mutexes/), and echoes it in the response header.

```go
type ctxKey string

const requestIDKey ctxKey = "requestID"

func (s *server) requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			b := make([]byte, 8)
			_, _ = rand.Read(b)
			id = hex.EncodeToString(b)
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`rand.Read` fills the slice with random bytes; the `_, _ =` throws away its two results, since in current Go it cannot fail. The key has its own type, `ctxKey`, so no other package can collide with it by accident. `r.WithContext` returns a copy of the request that carries the new context; requests are never edited in place.

The logging layer has a puzzle: the status code is chosen inside the handler, after `logging` has already handed over control. The fix is a small wrapper. `statusRecorder` embeds the real `http.ResponseWriter` (embedding is from [post 4](/blog/go-structs-methods-interfaces/)), so it gets all of its methods for free, and overrides only `WriteHeader` to remember the code.

```go
// statusRecorder remembers the status code a handler wrote.
type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (sr *statusRecorder) WriteHeader(code int) {
	sr.status = code
	sr.ResponseWriter.WriteHeader(code)
}

func (s *server) logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)
		id, _ := r.Context().Value(requestIDKey).(string)
		s.log.Info("request",
			"id", id, "method", r.Method, "path", r.URL.Path,
			"status", rec.status, "duration_us", time.Since(start).Microseconds())
	})
}
```

In `logging`, `Value(requestIDKey).(string)` is a *type assertion*: the context stores values as `any`, and `.(string)` asks for the string inside. The `, _` ignores the yes/no flag, so a missing ID becomes an empty string. `log/slog` writes structured logs: a message plus key-value pairs. Because this program builds a JSON handler in `main`, every line is a JSON object a log system can search by `status` or `id`. The Go blog's `slog` post covers levels, groups and custom handlers; this service needs only `Info` and `Error`.

The last layer is the safety net. If a handler panics, `net/http` already catches it, logs a stack trace and closes the connection, which the client sees as an empty reply. I checked with a handler that panics under `httptest.NewServer`: the client got `EOF`. The middleware gives a better answer: it uses `defer` and `recover` ([post 5](/blog/go-errors-defer-panic/)) to log the panic and send a clean `500` JSON error.

```go
func (s *server) recoverPanic(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				s.log.Error("panic in handler", "panic", fmt.Sprint(v))
				writeError(w, http.StatusInternalServerError, "internal error")
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

`recoverPanic` is the innermost layer, so `logging` still sees the `500` it writes. It only covers the handler's own goroutine. A panic inside a goroutine your handler starts is not caught here, and it ends the whole program.

## main: config, timeouts, graceful shutdown

Now the part that turns handlers into a server. Configuration comes from the environment, with a default, which is how containers are configured.

```go
func getenv(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}

func main() {
	if err := run(); err != nil {
		slog.Error("server stopped", "err", err)
		os.Exit(1)
	}
}
```

`run` holds the real work so that `main` can print one error and exit with code 1. A `main` that calls `os.Exit` directly would skip every `defer` below it.

```go
func run() error {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	s := &server{store: &store{}, log: logger}

	srv := &http.Server{
		Addr:              getenv("ADDR", ":8080"),
		Handler:           s.routes(),
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       10 * time.Second,
		WriteTimeout:      10 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	// ctx is cancelled when the process gets Ctrl+C or SIGTERM.
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	errc := make(chan error, 1)
	go func() {
		logger.Info("listening", "addr", srv.Addr)
		errc <- srv.ListenAndServe()
	}()

	select {
	case err := <-errc:
		return err // the server failed to start, e.g. the port is taken
	case <-ctx.Done():
	}

	logger.Info("shutting down")
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	return srv.Shutdown(shutdownCtx)
}
```

Read `run` in four steps.

1. **Build the server by hand.** `http.Server` is a struct, so the timeouts are plain fields. They are the guard from the opening quote.
2. **Start it in a goroutine.** `ListenAndServe` blocks until the server stops, so it runs in a goroutine and reports its error on a channel ([post 7](/blog/go-goroutines-channels-select/)). The channel has room for one value so the goroutine can always finish.
3. **Wait for the first of two events.** `signal.NotifyContext` gives a context that is cancelled on Ctrl+C or SIGTERM, the signal Docker and Kubernetes send to stop a container. `select` waits for that, or for the server failing to start.
4. **Shut down with a deadline.** `Server.Shutdown` closes the listener so no new connections arrive, then waits for running requests to finish. The 10-second context is the cap: if they take longer, `Shutdown` returns an error instead of hanging for ever.

The four timeouts are not interchangeable.

| Field | Limits | Value here |
|---|---|---|
| `ReadHeaderTimeout` | time to read the request headers | 5 s |
| `ReadTimeout` | time to read the whole request, body included | 10 s |
| `WriteTimeout` | time from end of request read to end of response write | 10 s |
| `IdleTimeout` | how long an idle keep-alive connection may wait | 60 s |

These numbers suit a small JSON API. A server that streams large downloads needs a bigger `WriteTimeout`. [Go in production](/blog/go-production-stdlib-cpu-cache-gc-kubernetes/) explains why they matter once real traffic arrives.

## Testing handlers with httptest

You do not need a running server to test handlers. A `Handler` is just a value with `ServeHTTP`, so a test builds a fake request with `httptest.NewRequest`, hands it a `httptest.NewRecorder` to write into, and inspects what was written. This is [post 6](/blog/go-testing-table-tests/)'s table test applied to HTTP.

```go
package main

import (
	"io"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func newTestServer() *server {
	return &server{store: &store{}, log: slog.New(slog.NewTextHandler(io.Discard, nil))}
}

func TestCreateTodo(t *testing.T) {
	tests := []struct {
		name       string
		body       string
		wantStatus int
	}{
		{"valid", `{"title":"learn Go"}`, http.StatusCreated},
		{"empty title", `{"title":""}`, http.StatusUnprocessableEntity},
		{"unknown field", `{"title":"x","owner":"me"}`, http.StatusBadRequest},
		{"not json", `hello`, http.StatusBadRequest},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			h := newTestServer().routes()
			req := httptest.NewRequest("POST", "/todos", strings.NewReader(tt.body))
			rec := httptest.NewRecorder()
			h.ServeHTTP(rec, req)
			if rec.Code != tt.wantStatus {
				t.Errorf("status = %d, want %d (body %s)", rec.Code, tt.wantStatus, rec.Body)
			}
		})
	}
}

func TestGetTodo(t *testing.T) {
	s := newTestServer()
	s.store.add("learn Go")
	h := s.routes()

	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, httptest.NewRequest("GET", "/todos/1", nil))
	if rec.Code != http.StatusOK {
		t.Fatalf("GET /todos/1 = %d, want 200", rec.Code)
	}
	if got := rec.Body.String(); got != `{"id":1,"title":"learn Go","done":false}`+"\n" {
		t.Errorf("body = %q", got)
	}

	for path, want := range map[string]int{"/todos/9": 404, "/todos/abc": 400} {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("GET", path, nil))
		if rec.Code != want {
			t.Errorf("GET %s = %d, want %d", path, rec.Code, want)
		}
	}
}

func TestMethodNotAllowed(t *testing.T) {
	rec := httptest.NewRecorder()
	newTestServer().routes().ServeHTTP(rec, httptest.NewRequest("DELETE", "/todos", nil))
	if rec.Code != http.StatusMethodNotAllowed {
		t.Errorf("DELETE /todos = %d, want 405", rec.Code)
	}
}

func TestRecoverPanic(t *testing.T) {
	s := newTestServer()
	boom := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { panic("boom") })
	rec := httptest.NewRecorder()
	chain(boom, s.requestID, s.logging, s.recoverPanic).ServeHTTP(rec, httptest.NewRequest("GET", "/", nil))
	if rec.Code != http.StatusInternalServerError {
		t.Errorf("status = %d, want 500", rec.Code)
	}
	if rec.Header().Get("X-Request-ID") == "" {
		t.Error("missing X-Request-ID header")
	}
}
```

`TestCreateTodo` is a table test: four bodies, four expected statuses, one loop. Each test builds its own server, so tests never share state. `TestRecoverPanic` builds the chain by hand around a handler that panics, because no real route should panic on purpose. The tests run through `routes()`, so the middleware and patterns are tested too, not only the handler functions.

## Ship it: one file, an empty image

Post 1 said a Go build gives you one file. Two build settings make that file safe to drop anywhere:

- `CGO_ENABLED=0` links no C library, so the file has no dependency on the machine's libc. This is what lets it run in an image with nothing in it.
- `GOOS` and `GOARCH` choose the target operating system and CPU, so you can build for Linux on a Mac without any other tools.

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o todo-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o todo-linux-arm64 .
```

`-trimpath` removes your local folder names from the binary, and `-s -w` drops symbol and debug tables to make it smaller. Here are the results from my Mac:

## Key takeaways

- **Build the `http.Server` yourself and set timeouts from the start.** `http.ListenAndServe` leaves them all off, and a slow or vanished client can hold a connection for ever.
- **Go 1.22 patterns do method and path routing.** `"GET /todos/{id}"` plus `r.PathValue("id")` replaces most router libraries. The mux sends 405 with an `Allow` header for free.
- **Guard every JSON body.** Cap its size, reject unknown fields, validate after decoding, and answer errors in one JSON shape.
- **A middleware is `func(http.Handler) http.Handler`.** The first one in the chain is the outermost. Keep `recover` innermost so logging still sees the 500.
- **Shut down on purpose.** `signal.NotifyContext` plus `Server.Shutdown` with a deadline lets running requests finish before exit.
- **Test through `routes()` with `httptest`.** You exercise patterns and middleware without opening a port.
- **`CGO_ENABLED=0` plus `GOOS`/`GOARCH` gives one file for any Linux box,** and that file can be the only thing in a `FROM scratch` image.

## Dữ liệu và store

Bắt đầu từ dữ liệu. Mỗi handler chạy trong goroutine riêng, nên hai request có thể đụng vào danh sách cùng lúc. Store bảo vệ slice bằng mutex, đúng như [bài 8](/blog/go-context-timeouts-mutexes/) trình bày.

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"strconv"
	"sync"
	"syscall"
	"time"
)
```

```go
// Todo is one item. The tags tell encoding/json which key names to use.
type Todo struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
	Done  bool   `json:"done"`
}

// store keeps todos in memory. The mutex protects the slice because every
// request runs in its own goroutine.
type store struct {
	mu    sync.Mutex
	todos []Todo
}

func (s *store) add(title string) Todo {
	s.mu.Lock()
	defer s.mu.Unlock()
	t := Todo{ID: len(s.todos) + 1, Title: title}
	s.todos = append(s.todos, t)
	return t
}

func (s *store) get(id int) (Todo, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	if id < 1 || id > len(s.todos) {
		return Todo{}, false
	}
	return s.todos[id-1], true
}

func (s *store) list() []Todo {
	s.mu.Lock()
	defer s.mu.Unlock()
	out := make([]Todo, len(s.todos)) // a copy, and [] (not null) when empty
	copy(out, s.todos)
	return out
}
```

Đoạn chữ trong dấu backquote sau mỗi field, `` `json:"id"` ``, gọi là *struct tag*. Nó là ghi chú gắn vào field, và `encoding/json` đọc nó để chọn tên key, nên `ID` được viết thành `"id"`. Có hai chi tiết dễ bỏ sót. `list` trả về một bản sao, nên bên gọi không bao giờ sửa được slice của store từ phía sau. Nó cũng dùng `make`, nên store trống cho ra JSON `[]` chứ không phải `null`, thứ mà nhiều client xử lý không nổi.

## Định tuyến theo method và đường dẫn

`ServeMux` là một bảng ánh xạ từ mẫu (pattern) sang handler. Trước Go 1.22 nó chỉ khớp đường dẫn, và người ta phải dùng thư viện router để khớp method và lấy `{id}`. Từ Go 1.22 bản chuẩn làm được cả hai: pattern có thể bắt đầu bằng method và chứa wildcard có tên, và handler đọc wildcard bằng `r.PathValue`.

```go
type server struct {
	store *store
	log   *slog.Logger
}

// routes wires patterns to handlers and wraps them in middleware.
func (s *server) routes() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", s.health)
	mux.HandleFunc("GET /todos", s.listTodos)
	mux.HandleFunc("POST /todos", s.createTodo)
	mux.HandleFunc("GET /todos/{id}", s.getTodo)
	// The first middleware listed is the outermost one.
	return chain(mux, s.requestID, s.logging, s.recoverPanic)
}

func (s *server) health(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

func (s *server) listTodos(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, s.store.list())
}

func (s *server) getTodo(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.Atoi(r.PathValue("id"))
	if err != nil {
		writeError(w, http.StatusBadRequest, "id must be a number")
		return
	}
	t, ok := s.store.get(id)
	if !ok {
		writeError(w, http.StatusNotFound, "todo not found")
		return
	}
	writeJSON(w, http.StatusOK, t)
}
```

Ở đây có ba điều mà bài về routing Go 1.22 mô tả.

- `"GET /todos/{id}"` chỉ khớp GET (và HEAD) trên `/todos/` cộng thêm đúng một đoạn. `r.PathValue("id")` trả đoạn đó dưới dạng string, và `strconv.Atoi` đổi nó thành số hoặc lỗi.
- Khi đường dẫn khớp mà method không khớp, mux tự trả `405 Method Not Allowed` và tự điền header `Allow`. Bạn sẽ thấy điều đó ở phần chạy thử bên dưới.
- Khi hai pattern cùng có thể khớp, pattern cụ thể hơn thắng, nên `GET /todos/{id}` và `GET /todos/latest` sống chung được.

Ta tạo mux riêng bằng `http.NewServeMux()`. Package còn có `http.DefaultServeMux` toàn cục, và package nào được import cũng có thể đăng ký route lên đó, như *Efficient Go* cảnh báo khi nói về `net/http/pprof`. Mux do bạn sở hữu chỉ có những route bạn tự viết.

## JSON vào, JSON ra

Endpoint nào cũng theo một khuôn: giải mã body, kiểm tra, làm việc, ghi câu trả lời JSON. Phần còn lại của `main.go` liên quan đến JSON gồm hai hàm ghi nhỏ và một handler có giải mã.

```go
type createRequest struct {
	Title string `json:"title"`
}

func (s *server) createTodo(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // refuse bodies over 1 MiB
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	var in createRequest
	if err := dec.Decode(&in); err != nil {
		writeError(w, http.StatusBadRequest, "invalid JSON: "+err.Error())
		return
	}
	if in.Title == "" || len(in.Title) > 100 {
		writeError(w, http.StatusUnprocessableEntity, "title must be 1 to 100 bytes")
		return
	}
	writeJSON(w, http.StatusCreated, s.store.add(in.Title))
}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(v); err != nil {
		slog.Error("write response", "err", err)
	}
}

func writeError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]string{"error": msg})
}
```

Phía giải mã là nơi service hay bị thương, nên có ba lớp bảo vệ.

1. `http.MaxBytesReader` giới hạn body ở 1 MiB. Thiếu nó, client gửi body to bao nhiêu server cũng đọc hết.
2. `DisallowUnknownFields` biến key gõ sai hoặc thừa thành lỗi thay vì lặng lẽ bỏ qua.
3. Việc kiểm tra title chạy sau khi giải mã. JSON parse được vẫn có thể sai.

Status code mang ý nghĩa. Body không phải JSON hợp lệ, hoặc có key ta không biết, là `400 Bad Request`: client gửi thứ ta không đọc được. Body là JSON hợp lệ nhưng vi phạm một quy tắc (title rỗng) là `422 Unprocessable Entity`: ta đọc được và từ chối. Có đội dùng 400 cho cả hai; chọn một quy tắc và giữ nhất quán. Lỗi luôn trả về dạng `{"error": "..."}`, để client chỉ phải parse một hình dạng.

Thứ tự trong `writeJSON` quan trọng: đặt header, rồi `WriteHeader`, rồi body. Sau `WriteHeader` dòng status đã đi tới client, nên nếu lỗi xảy ra lúc encode thì chỉ còn cách ghi log. Vì thế lỗi được ghi log chứ không được trả về.

## Middleware: hàm nhận handler, trả handler

Có việc thuộc về mọi request: gắn ID, ghi log, sống sót khi panic. Chép chúng vào từng handler chỉ thêm rối, nên Go dùng *middleware*. Middleware nhận `http.Handler` kế tiếp và trả về một handler mới: làm gì đó, gọi handler kế tiếp, và có thể làm thêm gì đó sau. Nó là một closure, từ [bài 5](/blog/go-errors-defer-panic/), nhớ lấy `next`.

```go
// A middleware takes a handler and returns a handler that does extra work around it.
type middleware func(http.Handler) http.Handler

func chain(h http.Handler, mws ...middleware) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}
```

Hai chỗ cú pháp: `mws ...middleware` nghĩa là `chain` nhận số middleware tùy ý, và `http.HandlerFunc(f)` biến một hàm thường thành `Handler`, nên mọi middleware bên dưới có thể trả về một function literal. `chain` bọc handler từ middleware cuối về đầu, nên **middleware đứng đầu danh sách là lớp ngoài cùng**. Quay lại `routes()`, `chain(mux, s.requestID, s.logging, s.recoverPanic)` nghĩa là request gặp `requestID`, rồi `logging`, rồi `recoverPanic`, rồi mới tới mux. Response đi ngược ra theo đúng đường đó.

Lớp đầu tiên gắn ID cho mỗi request. Nó giữ ID mà bên gọi gửi trong `X-Request-ID` (hữu ích khi gateway đã tạo sẵn) và nếu không có thì tạo 8 byte ngẫu nhiên. Nó để ID vào context của request, chính context ở [bài 8](/blog/go-context-timeouts-mutexes/), và lặp lại ID trong header response.

```go
type ctxKey string

const requestIDKey ctxKey = "requestID"

func (s *server) requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			b := make([]byte, 8)
			_, _ = rand.Read(b)
			id = hex.EncodeToString(b)
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`rand.Read` điền các byte ngẫu nhiên vào slice; `_, _ =` bỏ đi hai kết quả trả về của nó, vì ở Go hiện tại nó không thể lỗi. Key có kiểu riêng `ctxKey`, nên không package nào khác va chạm được với nó do tình cờ. `r.WithContext` trả về một bản sao của request mang context mới; request không bao giờ bị sửa tại chỗ.

Lớp logging có một câu đố: status code được chọn bên trong handler, sau khi `logging` đã trao quyền điều khiển đi. Cách giải là một wrapper nhỏ. `statusRecorder` nhúng (embed) `http.ResponseWriter` thật (embedding có ở [bài 4](/blog/go-structs-methods-interfaces/)), nên có sẵn mọi method của nó, và chỉ ghi đè `WriteHeader` để nhớ mã status.

```go
// statusRecorder remembers the status code a handler wrote.
type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (sr *statusRecorder) WriteHeader(code int) {
	sr.status = code
	sr.ResponseWriter.WriteHeader(code)
}

func (s *server) logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)
		id, _ := r.Context().Value(requestIDKey).(string)
		s.log.Info("request",
			"id", id, "method", r.Method, "path", r.URL.Path,
			"status", rec.status, "duration_us", time.Since(start).Microseconds())
	})
}
```

Trong `logging`, `Value(requestIDKey).(string)` là một *type assertion* (ép kiểu có kiểm tra): context lưu giá trị dưới dạng `any`, và `.(string)` đòi lấy string bên trong. Phần `, _` bỏ qua cờ có/không, nên thiếu ID thì ra chuỗi rỗng. `log/slog` ghi log có cấu trúc: một thông điệp kèm các cặp key-value. Vì chương trình này tạo JSON handler trong `main`, mỗi dòng là một object JSON mà hệ thống log tìm được theo `status` hay `id`. Bài về `slog` trên blog của Go nói về level, group và handler tùy biến; service này chỉ cần `Info` và `Error`.

Lớp cuối là lưới an toàn. Nếu handler panic, `net/http` vốn đã bắt được, ghi stack trace và đóng connection, và client thấy một phản hồi rỗng. Tôi đã kiểm tra bằng một handler panic chạy dưới `httptest.NewServer`: client nhận `EOF`. Middleware cho câu trả lời tốt hơn: nó dùng `defer` và `recover` ([bài 5](/blog/go-errors-defer-panic/)) để ghi log panic và gửi một lỗi `500` JSON gọn gàng.

```go
func (s *server) recoverPanic(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				s.log.Error("panic in handler", "panic", fmt.Sprint(v))
				writeError(w, http.StatusInternalServerError, "internal error")
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

`recoverPanic` là lớp trong cùng, nên `logging` vẫn thấy `500` mà nó ghi ra. Nó chỉ bao phủ goroutine của chính handler. Panic trong một goroutine do handler tự khởi chạy sẽ không bị bắt ở đây, và làm sập cả chương trình.

## main: cấu hình, timeout, tắt êm

Giờ là phần biến các handler thành một server. Cấu hình lấy từ biến môi trường, có giá trị mặc định, đó là cách container được cấu hình.

```go
func getenv(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}

func main() {
	if err := run(); err != nil {
		slog.Error("server stopped", "err", err)
		os.Exit(1)
	}
}
```

`run` giữ phần việc thật để `main` in ra một lỗi rồi thoát với mã 1. Nếu `main` gọi thẳng `os.Exit`, mọi `defer` bên dưới sẽ bị bỏ qua.

```go
func run() error {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	s := &server{store: &store{}, log: logger}

	srv := &http.Server{
		Addr:              getenv("ADDR", ":8080"),
		Handler:           s.routes(),
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       10 * time.Second,
		WriteTimeout:      10 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	// ctx is cancelled when the process gets Ctrl+C or SIGTERM.
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	errc := make(chan error, 1)
	go func() {
		logger.Info("listening", "addr", srv.Addr)
		errc <- srv.ListenAndServe()
	}()

	select {
	case err := <-errc:
		return err // the server failed to start, e.g. the port is taken
	case <-ctx.Done():
	}

	logger.Info("shutting down")
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	return srv.Shutdown(shutdownCtx)
}
```

Đọc `run` theo bốn bước.

1. **Tự dựng server.** `http.Server` là một struct, nên timeout chỉ là các field bình thường. Đó là lớp bảo vệ từ câu trích ở đầu bài.
2. **Chạy nó trong goroutine.** `ListenAndServe` chặn cho tới khi server dừng, nên nó chạy trong goroutine và báo lỗi qua một channel ([bài 7](/blog/go-goroutines-channels-select/)). Channel chứa được một giá trị để goroutine luôn kết thúc được.
3. **Chờ sự kiện nào đến trước trong hai.** `signal.NotifyContext` cho ra một context bị hủy khi nhấn Ctrl+C hoặc nhận SIGTERM, tín hiệu mà Docker và Kubernetes gửi để dừng container. `select` chờ tín hiệu đó, hoặc chờ server không khởi động được.
4. **Tắt với hạn chót.** `Server.Shutdown` đóng listener để không connection mới nào vào, rồi chờ các request đang chạy làm xong. Context 10 giây là mức trần: nếu chúng lâu hơn, `Shutdown` trả về lỗi thay vì treo mãi.

Bốn timeout không thay thế nhau được.

| Field | Giới hạn | Giá trị ở đây |
|---|---|---|
| `ReadHeaderTimeout` | thời gian đọc header của request | 5 s |
| `ReadTimeout` | thời gian đọc cả request, gồm body | 10 s |
| `WriteTimeout` | thời gian từ khi đọc xong request đến khi ghi xong response | 10 s |
| `IdleTimeout` | một connection keep-alive rảnh được chờ bao lâu | 60 s |

Những con số này hợp với một JSON API nhỏ. Server stream file tải lớn cần `WriteTimeout` lớn hơn. [Go trên production](/blog/go-production-stdlib-cpu-cache-gc-kubernetes/) giải thích vì sao chúng quan trọng khi có traffic thật.

## Test handler với httptest

Bạn không cần server đang chạy để test handler. `Handler` chỉ là một giá trị có `ServeHTTP`, nên test tạo một request giả bằng `httptest.NewRequest`, đưa cho nó một `httptest.NewRecorder` để ghi vào, rồi kiểm tra thứ đã được ghi. Đây là table test của [bài 6](/blog/go-testing-table-tests/) áp dụng cho HTTP.

```go
package main

import (
	"io"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func newTestServer() *server {
	return &server{store: &store{}, log: slog.New(slog.NewTextHandler(io.Discard, nil))}
}

func TestCreateTodo(t *testing.T) {
	tests := []struct {
		name       string
		body       string
		wantStatus int
	}{
		{"valid", `{"title":"learn Go"}`, http.StatusCreated},
		{"empty title", `{"title":""}`, http.StatusUnprocessableEntity},
		{"unknown field", `{"title":"x","owner":"me"}`, http.StatusBadRequest},
		{"not json", `hello`, http.StatusBadRequest},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			h := newTestServer().routes()
			req := httptest.NewRequest("POST", "/todos", strings.NewReader(tt.body))
			rec := httptest.NewRecorder()
			h.ServeHTTP(rec, req)
			if rec.Code != tt.wantStatus {
				t.Errorf("status = %d, want %d (body %s)", rec.Code, tt.wantStatus, rec.Body)
			}
		})
	}
}

func TestGetTodo(t *testing.T) {
	s := newTestServer()
	s.store.add("learn Go")
	h := s.routes()

	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, httptest.NewRequest("GET", "/todos/1", nil))
	if rec.Code != http.StatusOK {
		t.Fatalf("GET /todos/1 = %d, want 200", rec.Code)
	}
	if got := rec.Body.String(); got != `{"id":1,"title":"learn Go","done":false}`+"\n" {
		t.Errorf("body = %q", got)
	}

	for path, want := range map[string]int{"/todos/9": 404, "/todos/abc": 400} {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("GET", path, nil))
		if rec.Code != want {
			t.Errorf("GET %s = %d, want %d", path, rec.Code, want)
		}
	}
}

func TestMethodNotAllowed(t *testing.T) {
	rec := httptest.NewRecorder()
	newTestServer().routes().ServeHTTP(rec, httptest.NewRequest("DELETE", "/todos", nil))
	if rec.Code != http.StatusMethodNotAllowed {
		t.Errorf("DELETE /todos = %d, want 405", rec.Code)
	}
}

func TestRecoverPanic(t *testing.T) {
	s := newTestServer()
	boom := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { panic("boom") })
	rec := httptest.NewRecorder()
	chain(boom, s.requestID, s.logging, s.recoverPanic).ServeHTTP(rec, httptest.NewRequest("GET", "/", nil))
	if rec.Code != http.StatusInternalServerError {
		t.Errorf("status = %d, want 500", rec.Code)
	}
	if rec.Header().Get("X-Request-ID") == "" {
		t.Error("missing X-Request-ID header")
	}
}
```

`TestCreateTodo` là table test: bốn body, bốn status mong đợi, một vòng lặp. Mỗi test tạo server riêng, nên các test không bao giờ dùng chung trạng thái. `TestRecoverPanic` dựng chuỗi bằng tay quanh một handler panic, vì không route thật nào nên panic có chủ đích. ## Đóng gói: một file, một image rỗng

Bài 1 đã nói build Go cho ra một file. Hai thiết lập build làm file đó thả đâu cũng chạy:

- `CGO_ENABLED=0` không liên kết thư viện C nào, nên file không phụ thuộc libc của máy. Chính điều này cho phép nó chạy trong image không có gì.
- `GOOS` và `GOARCH` chọn hệ điều hành và CPU đích, nên bạn build cho Linux ngay trên Mac mà không cần công cụ nào khác.

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o todo-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o todo-linux-arm64 .
```

`-trimpath` xóa tên thư mục trên máy bạn khỏi binary, và `-s -w` bỏ bảng symbol và bảng debug để file nhỏ hơn. Đây là kết quả trên máy Mac của tôi:

Giờ là container. Image thường chứa cả một hệ điều hành. Image `FROM scratch` thì rỗng, và Dockerfile chép đúng một file vào đó. Giai đoạn đầu build bằng image Go; giai đoạn hai chỉ giữ lại binary.

```dockerfile
FROM golang:1.27 AS build
WORKDIR /src
COPY go.mod ./
COPY *.go ./
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /todo .

FROM scratch
COPY --from=build /todo /todo
EXPOSE 8080
ENTRYPOINT ["/todo"]
```

Cả image nặng 8,86 MB trên đĩa, và binary bên trong chiếm phần lớn. Trong đó không có shell, không có package manager, không có libc, nghĩa là kẻ tấn công cũng chẳng có gì để dùng thêm. Hai lưu ý:

- Không có shell thì không `docker exec` vào xem được. Hãy debug bằng log, hoặc tạm build từ image nền như `gcr.io/distroless/static` có thêm một root filesystem tối thiểu.
- Nếu service gọi endpoint HTTPS, nó cần chứng chỉ root CA, thứ mà `scratch` không có. Hãy chép chúng từ giai đoạn build sang, hoặc dùng nền distroless.

Cuối cùng, `docker stop` gửi SIGTERM tới tiến trình của ta, vốn là PID 1 trong container. Lệnh stop trong lần chạy của tôi trả về sau 0,17 giây: tiến trình đang rảnh nên `Shutdown` không có gì để chờ. Trên Kubernetes, hãy đặt thời gian termination grace period của pod dài hơn timeout tắt của bạn.

## Key takeaways

- **Tự dựng `http.Server` và đặt timeout ngay từ đầu.** `http.ListenAndServe` tắt hết các timeout, và một client chậm hoặc biến mất có thể giữ connection mãi mãi.
- **Pattern của Go 1.22 lo việc định tuyến theo method và đường dẫn.** `"GET /todos/{id}"` cùng `r.PathValue("id")` thay được phần lớn thư viện router. Mux gửi 405 kèm header `Allow` miễn phí.
- **Bảo vệ mọi body JSON.** Giới hạn kích thước, từ chối key lạ, kiểm tra sau khi giải mã, và trả lỗi theo một dạng JSON.
- **Middleware là `func(http.Handler) http.Handler`.** Cái đứng đầu chuỗi là lớp ngoài cùng. Để `recover` ở trong cùng để logging vẫn thấy mã 500.
- **Tắt có chủ đích.** `signal.NotifyContext` cùng `Server.Shutdown` có hạn chót để request đang chạy xong trước khi thoát.
- **Test qua `routes()` bằng `httptest`.** Bạn thử cả pattern và middleware mà không mở cổng nào.
- **`CGO_ENABLED=0` cùng `GOOS`/`GOARCH` cho ra một file chạy trên máy Linux bất kỳ,** và file đó có thể là thứ duy nhất trong image `FROM scratch`.
